# 拖拽与导入问题核查

## 已确认的问题

- [Issue #18](https://github.com/zyjGraphein/Obsidian-EagleBridge/issues/18) 涉及 0.3.3 的整库 chokidar 监控。历史代码的 `depth: 1` 仍覆盖所有素材目录，监控器没有保存在可清理的字段中，停止服务时只关闭 HTTP 服务。当前工作区在此前的多库改造中已移除监控调用，本次删除剩余的 chokidar 依赖。
- 当前上传逻辑仍会对所有 `.info` 目录执行 `stat`，按修改时间排序后找同名素材；最多重复 24 次。API 成功与本地目录可见性是两个不同条件，因此可能出现已经导入却无法返回链接，也可能匹配同名旧素材。
- 素材库归属原先仅比较路径字符串，同一目录的别名、符号链接，以及 macOS 的大小写或 Unicode 路径表示差异可能使现有素材被当作外部文件上传。
- 一批文件中的后续导入失败会丢弃之前已经成功解析的全部链接；Canvas 的文件解析异常没有在事件入口捕获。

## 修复方式

- 文件使用 `/api/item/addFromPaths`，单文件也作为一项提交。直接使用响应中的素材 ID 构造链接，不读取新素材的目录、元数据或文件事件，也不会因缺少 ID 自动重复上传。
- 使用去掉扩展名的文件名作为 Eagle 的素材名称，保留原始文件名用于 Obsidian 链接。
- 网页书签优先使用响应中的 ID；没有 ID 时，在 Eagle API 中有界查询新书签，排除导入前的 ID，并核对 URL 和创建时间。无法唯一确认时提示用户从 Eagle 拖入已有素材，避免插入猜测的链接。
- 路径不一致时核对实际目录的设备号和 inode，兼顾外接盘、目录别名及大小写敏感的文件系统。未配置的 Eagle 源库会提示添加配置，不会再次导入。
- 保留多文件操作中已成功的链接，统一提示失败原因；捕获预览端口被其他 Obsidian 仓库占用时的错误。

文件导入需要 Eagle 4 或更新版本。官方 [Eagle 4 更新说明](https://www.eagle.cool/blog/post/eagle4) 明确列出 `addFromPaths` 返回文件 ID 的能力；旧版 [HTTP API 示例](https://api.eagle.cool/item/add-from-paths) 仅展示成功状态，不能据此假设单文件接口也返回 ID。

## 验证

- `npm run test:transfer`：无目录事件及无本地元数据时插入 Markdown 链接、失败响应、缺失 ID 不重试上传、部分成功、真实目录别名、未配置库、多库串行操作、书签 API 查询、模拟 macOS 路径身份、预览端口冲突、连续启动和停止服务。
- `npm run test:resolver`：原有文件解析测试。
- `npm run build`：TypeScript 检查与生产构建。
- Windows 本机 Eagle 4.0.0 实际调用确认 `addFromPaths` 返回 `data: ["素材ID"]`。探针素材已通过 Eagle API 移入回收站。
- 重载实际 Obsidian 插件后，通过插件的拖入解析接口导入临时 SVG，成功返回 Markdown 链接；预览请求返回 HTTP 200，页面图片加载完成且原始尺寸为 240×80。测试笔记和临时文件已清理，Eagle 测试素材移入回收站。重载及导入期间未新增控制台错误。

没有 macOS 实机环境。外接盘和 iCloud 的系统事件行为尚未实测，也不能把用户提供的 FSEvents 解释当作已证实的根因。修复后的链接插入流程不再依赖这类事件；图片预览仍需要素材在本地可读。

## 后续：编辑点击与视频批量迁移

- 编辑区左键原先会查找光标所在行的 URL 并打开 Eagle 菜单，范围判断没有排除 URL 前方的图片名和尺寸。现仅保留阅读视图中原有的链接点击菜单，编辑区的普通左键由编辑器处理，右键菜单保留。
- 当前文档批量命令原本已支持视频，无图片扩展名限制；它通过文件路径调用 Eagle API，不把视频内容读入内存。本次增加进度提示、防止同时重复运行、保留部分成功回链，并固定使用命令开始时的页面标签。
- 删除源附件前核对源文件是否变化、Eagle 文件副本是否就绪及大小是否相符。Eagle 返回 ID 后可能延迟写入元数据，因此仅在删除阶段按 ID 短暂核对这个素材，超时保留源文件。该检查不等同于逐字节校验，也不会阻塞回链写入或扫描整库。
- 上传期间出现文档或引用变化、引用缓存不完整、Canvas 无法解析、其他页面/属性仍引用源文件时，保留源附件。YAML 中以普通字符串存储的附件路径也纳入保留检查；不改写属性值。
- HTTP 视频预览保留 Range 支持；HEAD 不读取文件内容，中断预览时关闭对应文件流。

验证：

- 实际 Obsidian 编辑器中分别左键点击图片名、`|550` 和 URL，没有阻止默认行为或弹出菜单；右键仍出现 Open / Copy / Properties / Delete，尺寸可改为 600。
- `npm run test:batch` 覆盖视频迁移、重复引用、部分失败、YAML/共享引用、源文件变化、复制未完成、元数据延迟、重复执行与监听器清理。8 GiB 场景模拟的是文件大小元数据，并非真实 8 GiB 文件传输性能测试。
- `npm run test:transfer` 额外覆盖视频 HEAD、Range 和预览中断后的文件流清理。
- 用实际 MP4 运行现有命令，正文引用被替换、YAML 保持原样、源视频移入回收站。Eagle 副本大小一致，链接能加载视频元数据（160×90）。临时笔记已清理，Eagle 测试素材已移入回收站。

能力边界：此命令只处理当前文档正文中的标准附件引用，不是跨多文档批量迁移。YAML 路径替换和第三方卡片视图的通用视频缩略图适配尚未实现。

可回复用户：

> 已有的「Upload current Markdown attachments to Eagle」命令支持视频，可自行绑定快捷键。打开目标文档运行后，会迁移正文引用的本地附件并替换为 Eagle 链接；确认副本完整且没有其他引用后，源附件会移入回收站。视频按路径交给 Eagle，不会整段读入 Obsidian 内存。本次维护补上了进度、部分失败处理和源文件保留检查。当前仍按单篇文档运行，YAML 属性保持原样；跨多篇文档迁移和第三方卡片视频缩略图尚不支持。

## 后续：视频预览与自动播放

- 实时预览原先在 Markdown 图片语法之后追加 iframe，Obsidian 的原生图片占位和图片工具栏仍然存在。现由装饰替换完整嵌入范围；阅读模式同时替换图片的包裹元素。
- MP4 直接放入 iframe 会进入浏览器的媒体页面并自动播放。现使用带播放控件的原生 video，默认暂停、仅预加载元数据。空文件名或自定义标题通过 HEAD 的 MIME 类型识别视频；普通图片仍显示为图片，书签重定向保留 iframe。
- 视图隐藏时暂停媒体，销毁预览时取消请求并释放媒体源。播放控件使用原生交互，保留 Eagle 右键菜单。

实际 Windows Obsidian 验证：

- 使用反馈中的视频链接，在实时预览与阅读模式分别检查带文件名、空文件名嵌入：各显示两个 video，没有对应的 img 或图片工具栏，也不使用视频 iframe。
- 打开后均为 `paused=true`、`currentTime=0`、`autoplay=false`；通过真实鼠标事件点击播放控件后开始播放。切换模式后隐藏的播放器暂停，新预览保持暂停。
- 已有图片与空文件名图片均加载成功，`image.png|120` 仍显示为 120 像素宽；普通视频链接保留为链接，代码块中的示例不生成播放器。
- 光标移动不重建播放器；切换到其他笔记后，两种视图的旧播放器都已移除 src 并暂停。
- `npm run build`、`test:transfer`、`test:resolver`、`test:batch` 均通过。没有 macOS 实机验证。
